# Insight Generator Specification

## Statistical safety

The generator reuses, rather than reimplements:

- `HolmBonferroniController`
- `DeterministicBootstrapValidator`

from the established QBP-3 statistical validation layer.

## Multiple-comparison rule

Every family of tested features or condition combinations must declare its hypothesis family before evaluation. Post-hoc search over arbitrary condition combinations without multiplicity accounting is forbidden.

## Required insight fields

- `insight_id`
- `hypothesis_family_id`
- `statement`
- `association_class`
- `sample_size`
- `effective_sample_size`
- `cohort_counts`
- `effect_size`
- `confidence_interval`
- `raw_p_value` where applicable
- `adjusted_threshold` / multiplicity result
- `bootstrap_result`
- `policy_scope_id/hash`
- `dataset_bundle_id`
- `limitations[]`
- `insight_sha256`

## Vocabulary

Allowed conclusion classes reuse project language:

- `UNOBSERVABLE`
- `INCONCLUSIVE`
- `ASSOCIATED`
- `ROBUST_ASSOCIATION`

No insight may state that a condition “causes”, “guarantees”, or “will win”. Example wording:

> In dataset LDS-…, this predeclared condition set was associated with a higher observed WIN rate; n=…, 95% CI=…, multiplicity-adjusted result=…, bootstrap stability=….

## Condition conjunctions

Multi-feature conjunctions are permitted only when predeclared or generated by an explicitly bounded search protocol whose full candidate count is supplied to the multiplicity controller.
